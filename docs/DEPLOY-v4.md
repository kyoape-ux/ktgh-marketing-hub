# v4 換軌部署指南（Drive JSON 成為主資料來源）

> 這一版要解決的是：匯入的貼文、活動成果報告文字、活動照片、彈性曝光來源
> 每次重新整理就消失。根因是「開頁自動同步 = 用 Google Sheets 整包覆蓋本機」，
> 而 Sheets 只有 12 個欄位、寫入又走網址（GET）長度必爆。

## 換軌後的資料流

```
              ┌──────────────────────────┐
              │  Google Drive JSON        │  ← 唯一真實來源，無大小限制
              │  ktgh_marketing_state.json│     欄位想加就加
              └───────┬──────────┬────────┘
       loadState      │          │  saveState（POST，不受網址長度限制）
                      ▼          │
              ┌──────────────────┴────────┐
              │  行銷整合分析中心（網頁）  │
              └───────────────────────────┘
                      │ saveState 時由 GAS 自動鏡像
                      ▼
              ┌───────────────────────────┐
              │  Google Sheets（唯讀鏡像） │  ← 給同事查看／做樞紐分析
              │  在這裡改不會回流          │
              └───────────────────────────┘
```

## 步驟 1：更新 Apps Script（只有你能做，約 3 分鐘）

1. 開 https://script.google.com ，進入行銷資料庫那個專案
   （試算表 ID `1MtKTbrcoxP7-YVUB0rILdYrM3vOh_O0JXqEWNdJFrKI`）
2. 開啟 `Code.gs`，**全選刪除**
3. 把 `scripts/apps-script-backend.gs` 的內容**整份貼上**、存檔
4. 上方函式選單選 `initSheets` → 按執行一次
   （會把 events 工作表的標頭補成新的 23 欄；前 12 欄順序不變，既有資料不動）
5. 右上「部署」→「管理部署作業」→ 編輯（鉛筆）→ 版本選「新版本」→ 部署
   - 執行身分：**我**
   - 存取權限：**所有人**
6. 部署後的網址若有變，貼給我；沒變就不用動

> 前端有相容處理：後端還沒更新也能運作（會退回讀整包推導版本），
> 只是 Sheets 鏡像要等後端更新才會生效。

## 步驟 2：組長做一次性搬遷（約 1 分鐘）

1. 用**組長**身分登入行銷整合分析中心
2. 開頁會跳出「雲端尚未建立完整主資料檔…要開始嗎？」→ 按確定
3. 系統會把「本機現有資料 ＋ Sheets 現有資料」合併後寫進 Drive
4. 右上角出現「已存雲端 HH:MM」＝ 完成

搬遷前系統會自動建立還原點（「資料備份」可復原）。

## 步驟 3：驗收

| 測項 | 做法 | 應該看到 |
|---|---|---|
| 成果報告存得住 | 填一場活動的目的／內容／觀察／改善 + 上傳 3 張照片 → 重新整理 | 內容與照片都還在 |
| 跨電腦看得到 | 換另一台電腦開啟 | 同一份內容 |

## 這一版改了什麼

**前端 `index.html`**

| 位置 | 改動 |
|---|---|
| 開頁流程 | `syncFromGAS()`（會覆蓋）→ `cloudBoot()`（從 Drive 載入） |
| `syncFromGAS()` | 改成「只補、不刪、不覆蓋」，並移出自動執行；按鈕改名「從 Sheets 補資料」 |
| `saveStore()` | 加容量偵測（原本 `catch(e){}` 是空的）；不再把照片寫進 localStorage；自動排程雲端存檔 |
| `_gasWrite()` | 停用。舊寫法用 GET 塞網址，28 篇貼文就超過 Google 的 8KB 上限 |
| `confirmImport()` | 拿掉手打「確認匯入」；改為等雲端存檔完成才回報成功 |
| `requireEdit()` | 雲端未就緒時擋下所有編輯，避免不完整的本機資料反覆蓋雲端 |
| `takeSnapshot()` | 快照不再存照片 |
| 新增 | `cloudBoot / runCloudSave / migrateToCloud / _stateMeta` 等雲端主資料層 |
| 新增 | 頂部唯讀警示橫幅 `#cloudBanner` |

**後端 `scripts/apps-script-backend.gs`**

| 改動 | 說明 |
|---|---|
| `events` schema 擴充 | 12 欄 → 23 欄，補上 sample／yt／utmCampaign／tags／channels／成果報告四欄／照片張數 |
| `saveState` 加把關 | JSON 解析不過或缺 posts/events 就拒絕寫入，不會被壞資料洗掉 |
| `saveState` 加鏡像 | 寫完 Drive 後自動把基本欄位鏡像到 Sheets |
| 新增 `stateMeta` | 輕量狀態查詢，供前端做衝突偵測與存檔確認 |
| 新增自動備份 | 每小時最多一份，保留最近 10 份，放在同一個 Drive 資料夾 |

## 安全機制

- **衝突偵測**：存檔前比對雲端版本。別人改過就停下來問「重新載入」還是「覆蓋」，不會悶頭蓋掉。
- **筆數驟減保護**：本機資料比雲端少三成以上就攔下來，需要二次確認才寫入。
- **存檔確認**：iframe POST 讀不到回應，所以每次存完都回讀確認版本號相符才顯示成功。
- **唯讀保護**：雲端載不到就整站唯讀，寧可不能編輯，也不讓不完整的本機資料覆蓋雲端。
- **雙層備份**：前端還原點（最近 5 份）＋ Drive 端自動備份（最近 10 份）。
